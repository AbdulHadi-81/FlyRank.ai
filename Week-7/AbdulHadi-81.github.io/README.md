# Abdul Hadi — Portfolio

Live at: https://abdulhadi-81.github.io/

A 4-page static portfolio site built to prove one claim: I design and build AI
agents that independently evaluate real, messy input and produce structured
judgment — not just call an API and return text.

## Pages

| Page | File | Purpose |
|---|---|---|
| Home | `index.html` | The claim, stated directly, with a generated node-network hero background |
| Work | `work.html` | Case studies — led by the Resume Analyzer (the actual proof), plus the CRUD API and Postgres migration projects |
| About | `about.html` | Real photo, background, current stack |
| Contact | `contact.html` | Email, LinkedIn, GitHub |

## Stack

Plain static HTML, CSS, and a couple of inline SVGs — no framework, no build
step, no backend. Chosen deliberately over React/Next.js or a static site
generator: it matches my actual skill level (strong HTML/CSS/JS, weaker at
architecture/tooling from scratch), the site's content is almost entirely
static, and nothing on it needs to run live except the external projects it
links out to. Full reasoning is in my AI Fluency track submission on stack
choice.

Fonts (Fraunces, Inter, IBM Plex Mono) load from Google Fonts via
`style.css`'s `@import`. Everything else is self-contained.

## Structure

```
index.html      Home / hero
work.html       Work / case studies
about.html      About
contact.html    Contact
style.css       Shared styles (single stylesheet, CSS variables for theme)
assets/         Real photo + Resume Analyzer screenshots
```

Each HTML page repeats the same `<nav>` and `<footer>` markup rather than
using includes — a deliberate trade-off for a plain static site with no build
step: editing shared nav/footer means touching all 4 files by hand, which is
a known, accepted limitation at this size (see "still ugly" list in my
submission).

## Design

- Background: warm cream (`#F7F4EC`), matching my identity kit
- Accent: single warm orange (`#D2622F`), used sparingly — one CTA button,
  one hero node, checkmarks — never as a background or repeated decoration
- Type: Fraunces (serif, headings) + Inter (body) + IBM Plex Mono (labels,
  eyebrows, captions)
- Hero background: a generated node-network SVG (nodes + edges, one accent
  node) — meant to read as a reasoning graph, not generic tech decoration

## Run locally

No build step. Open `index.html` directly in a browser, or serve the folder:

```bash
python -m http.server 8000
```

Then visit `http://localhost:8000`.

## Deploy

Hosted on GitHub Pages from this repo's `main` branch. Any push to `main`
updates the live site within about a minute.

## Known limitations ("still ugly")

- The 3 Resume Analyzer screenshots are cropped from a summary document, not
  the original app — resolution is lower than ideal and text is hard to read
  at full zoom.
- The Resume Analyzer itself has a known bug: results generated by the
  Mistral API get mislabeled "Local backup" in its UI, because the label
  check only looks for an OpenAI key. Disclosed openly in the case study
  rather than hidden.
- Nav and footer markup is duplicated across all 4 pages (no templating/build
  step) — editing either means updating 4 files by hand.
- No resume/CV download link yet on the Contact page.
